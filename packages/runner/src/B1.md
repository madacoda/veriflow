## Integration

`PlaywrightSessionFactory` is exported from `browser-session.ts`. Construct it with `{ storageRoot }`, using the same trusted persistent storage root as P1. It implements SessionFactory and returns BrowserSession. The coordinator supplies runId, allowedOrigins, optional viewport and artifactDirectory, then passes the same session to the AI tool adapter. Call evidence() before marking a run terminal and always await close().

Dev 1 owns the manifest change needed to expose this implementation as `@veriflow/runner/browser` with export `./browser: ./src/browser-session.ts`, and production composition/runtime dependency wiring. No manifest or core edits are included in B1. Chromium must be installed on the execution host. The default launch is headless with a 30-second launch bound. The optional launchBrowser injection is a trusted test/deployment seam and must return a Chromium browser.

Every open allocates a separate browser/context. A run abort closes its session. Command calls are serialized and concurrent calls reject. Invalid commands reject before browser execution. Actionability errors, lost browser connections, timeouts and capture failures throw. Missing/ambiguous targets and rejected origins return blocked; assertion mismatches return failed with final observed expected/actual strings. HTTP error responses return blocked prerequisites.

The adapter reserves 25 percent of each command timeout for screenshot finalization. Locator readiness and exact-value assertions poll within the remaining budget. The caller's abort/deadline remains authoritative and can terminate sooner. Output expected/actual values are capped at 2,000 characters. Use a realistic budget for screenshots, especially on CI.

## Origin policy

Only configured credential-free HTTP(S) origins may be requested. Chromium's Fetch interception checks every request, including redirected navigation before it reaches the destination. Playwright routing additionally rejects secondary frames and popup requests. Service workers are disabled, WebSockets are closed, dialogs dismissed and downloads disabled. These restrictions fit the single-page demo target. This is an origin boundary, not an operating-system network sandbox or a DNS/IP allowlist.

The tests assert zero requests arrive at a forbidden server for navigation redirects, action-triggered redirects, popup redirects and requests during screenshot capture. A same-origin redirect succeeds. Policy is rechecked after capture/observation; an unreported late policy violation makes evidence finalization reject. Navigation URLs containing credentials now reject at command validation through P3's shared URL schema, with additional browser policy checks.

## Observations and evidence

Observation body text is capped at the requested 1–20,000 characters, title at 256, URL at 2,048 and target list at 50 exact label/test-ID descriptions of at most 128 characters each. URL queries/fragments are removed. Text excludes input values through innerText. Treat observed page content as untrusted and never as instructions. Only run fixtures or authorized sites with suitable data handling; arbitrary page text or screenshots can contain sensitive application data. Password inputs are masked in screenshots. This is not a general-purpose secret redactor.

Each completed step captures a real PNG with a UUID filename under `runs/<runId>/`. Metadata preserves the supplied run and step IDs. Paths reject traversal, another run's directory, and symlink descendants under the trusted storage root. The root must be controlled by the service and protected from concurrent untrusted filesystem writers.

Capture files are written before the step returns. evidence() closes browser resources and returns a copy of the finalized artifact list. Repeated evidence()/close() calls are safe. A failed screenshot write causes evidence() to reject rather than report a complete capture. P1 should continue to classify media completeness conservatively until the core interface supports an explicit declaration.
